Todos los documentos deben estar organizados por carpetas con el nombre **UTxx** (Ej. UT01), y dentro de cada carpeta el nombre de cada práctica debe ser **Pxx** (Ej, P01).

Toda la documentaición de cada práctica debe incluir los siguientes elementos:
1. Pantallazos de ejecucuón.
2. Instrucciones empeladas.
3. Incidencias detectadas.
4. Páginas web consultadas.

> **El no cumplimiento de estas normas supondrá la calificación como "no válida" de la práctica.**


## UT01
### P01 - MARKDOWN 
El alumno debe escribir un docuemnto en formato markdown que  incluiya los siguientes elementos:

- LISTA DESORDENADA
- ESTILOS DE TEXTO : ENCABEZADO, NEGRITA, CURSIVO
- IMAGENES
- ENLACES
- BLOQUE DE CODIGO (DECIR ALGUNO QUE NOS GUSTE) JAVA, HTML, ETC

## UT05

Para evaluar GIT, es ncesario realizar las siguientes tareas:
### P01 - CONFIGURACIÓN INICIAL DE GIT 
Se comprobará que el usuario tiene bien configurado git en el PC (se hace in situ)
### P02 - [RAMAS Y CONFLICTOS](https://joaquinalbares.github.io/ut05/2024/12/03/ramas-y-conflictos.html)
Se debe hacer un documento con pantallazos donde se oberve la creación de ramas,el conflicto y su resolución. Se deberá acompañar comprimido el repositorio donde se han hecho las prácticas.

### P03 - [REPOSITORIO REMOTO](https://joaquinalbares.github.io/ut05/2024/11/28/repositorios_remotos.html)
Se debe crear un repositorio en GutHub, hacer una copia en local (checkout o clone) , modificar o crear dos archivos y subir a remoto el commit con los cambios. 
Todo el trabajo debe ser documentado con pantallazos del trabajo.

### EJERCICIOS DE CLASE
En clase, el profesor comprobará la conexión con el repositorio remoto, asi como la correcta conficguración de Git.
En la práctica de gitbrnaching, todo aquel que no la terminó en clase, debe enviar un docummento pantallazo de cada nivel superado y las instrucciones escritas en cada nivel
